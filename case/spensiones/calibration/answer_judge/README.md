# Answer-judge meta-evaluation sets (spensiones)

Reference labels to meta-evaluate the answer judges (`python -m agintis.cli.judge`) against: DeepSeek
`deepseek-chat` through the profile `judge` in `case/spensiones/llm_profiles.yaml`. Calibration data only
(never `eval_questions.jsonl`).

## Files

- `silver_labels_{in_dev,ood}.jsonl`: raw labels from 2 blind Claude labelers (opus, sonnet) produced by
  the `sa-label-eval` agent. A third labeler (fable) was discarded. Part 4.1c REPLACED these with a blind
  opus+sonnet relabel of the same golden dumps under the topic-based refusal rubric (judge v8+); the old
  v7-rubric labels are in git history before that commit.
- `silver_consensus_in_dev.jsonl`: the unanimous consensus of the labelers, bound by `answer_sha256`;
  regenerated from the new labels.
- `perturbations_{dev,test,test2}.jsonl`: controlled single-span error specs generated by Claude Opus.
  Types: `negation`, `condition_inversion`, `condition_deletion` (test2 only), `quantifier`,
  `number_date`, `entity_swap`, `unsupported_addition`.
- `perturbation_labels_{dev,test2}.jsonl`: labels by construction (originals true, perturbed false;
  citation truth for the originals comes from the silver consensus).

## Dumps (not versioned)

The answer dumps the labels bind to (`answer_sha256`) are corpus text plus model outputs, so they are
gitignored: `case/spensiones/judge/golden/` (`in_dev`, `ood`) and `case/spensiones/judge/`
(`p5_dev_answers.jsonl`, `p5_test2_answers.jsonl`). Regenerating them with `cli.dump_answers` gives
different answers, so the labels would no longer bind. Generator at dump time: gpt-5.4-mini at git
`87f5d2e`.

## Splits

33 consensus-faithful `in_dev` records, split by alternating sorted ids: dev (17) is used for prompt
tuning, test (16) is held out.

## Reproduce

Keys come from the environment, never from files: `read -rs OPENAI_API_KEY && export OPENAI_API_KEY`
(generator) and `read -rs DEEPSEEK_API_KEY && export DEEPSEEK_API_KEY` (judge profile).

```
export LLM_PROFILES_FILE=case/spensiones/llm_profiles.yaml OBSERVABILITY_TRACING=none
D=case/spensiones/calibration; A=$D/answer_judge; G=case/spensiones/judge/golden

# 1. dump (schema 1); same for ood.jsonl
uv run python -m agintis.cli.dump_answers --profiles case/spensiones/profiles \
  --agents case/spensiones/agents --agent spensiones-rag --questions $D/in_dev.jsonl \
  --out $G/in_dev_answers.jsonl --concurrency 4

# 2. perturbed dump + labels by construction (dev split shown; test2 likewise)
uv run python -m agintis.cli.perturb --answers $G/in_dev_answers.jsonl \
  --specs $A/perturbations_dev.jsonl --split dev --out case/spensiones/judge/p5_dev_answers.jsonl \
  --labels-out $A/perturbation_labels_dev.jsonl --citation-truth $A/silver_consensus_in_dev.jsonl

# 3. judge (exit 1 = some judgments errored, the report is complete)
uv run python -m agintis.cli.judge --profile judge --concurrency 4 \
  --answers case/spensiones/judge/p5_dev_answers.jsonl --report case/spensiones/judge/p5_dev_report.json

# 4. judge vs labels, per perturbation type
uv run python -m agintis.cli.agreement --labels $A/perturbation_labels_dev.jsonl \
  --judgments case/spensiones/judge/p5_dev_report.json --by-meta type \
  --answers case/spensiones/judge/p5_dev_answers.jsonl
```

Each CLI has `--help` for its arguments. Judge v7 adds the deterministic `script_mix` judge (non-Latin
letters inside Spanish text). Judge v8 defines a refusal by topic (no information on the asked topic; same
object/other aspect = partial, neighbouring object = refusal); v9 aligns the `is_refusal` schema
descriptions with that definition (single source: `src/agintis/agent_kit/judge/refusal_definition.py`).

## Judge v10 (part 4.2c)

v10 changes only `split_sentences` and the `citation_support` prompt: a fenced code block (```/~~~,
indent 0-3) stays whole and is glued only to an introducing sentence (ends with ':' or has no final
punctuation); markers right after the closing fence stick to the unit. The prompt asks to copy a cited
sentence with its whole block, because the verbatim guard needs `MIN_SENTENCE_COVERAGE` 0.90. Pure-prose
answers split exactly as v9 (only ood out-code-02 differs, verdict unchanged).

Regression on the golden dumps, v10 (2 runs) vs v9 (3 runs):

| set | judge | v9 | v10 |
|---|---|---|---|
| in_dev | citation_support | 82.9-88.6% | 82.9% |
| in_dev | faithfulness | 93.9-97% | 93.9% |
| in_dev | answer_relevance | 94.9% | 94.9% |
| in_dev | refusal_correctness | 94.9% | 94.9% |
| ood | all judges | 98.8-100% | 100% |

The v10 gain is measured on fastapi_es (see `case/fastapi_es/README.md`).

## Judge v11 (part 4.2d)

v11 makes the judge tolerant of code and source markup:

- Citation markers inside fenced blocks or inline code spans are not citations anywhere (`citation_support`,
  dangling precheck, refusal heuristic); sentences are never split inside an inline code span.
- `citation_numbers`/`dangling_citations` derive from the same per-sentence parse as `cited_sentences`.
- The evidence guard keeps `_` as a word character (`"__main__"` quotes pass); the short-fragment rule
  strips `_` before the watched-token check (`_no_`, `_sesenta_` rejected); paired `_` emphasis is
  unwrapped only around text without `_`.
- `JUDGE_VERSION` 11; the prompt hash record carries inline code.

Regression on the golden dumps, v11 (2 runs) vs v9-v10:

| set | judge | v9-v10 | v11 |
|---|---|---|---|
| in_dev | citation_support | 82.9-88.6% | 82.9-88.6% |
| in_dev | faithfulness | 93.9-97% | 93.9-97% |
| in_dev | answer_relevance | 94.9% | 94.9% |
| in_dev | refusal_correctness | 94.9% | 94.9% |
| ood | all judges | 98.8-100% | 100% |

The 4 ood faithfulness `no_claims` errors (out-chat-03/06/09, out-code-02) are identical in v9, v10 and v11.
